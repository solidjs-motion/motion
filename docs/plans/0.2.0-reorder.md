## 1. Why this plan exists

Reorder is the seventh in-scope feature of the 0.2.0 release (see
[0.2.0-layout-animations.md §1](0.2.0-layout-animations.md#1-why-this-plan-exists)).
It builds entirely on top of the six layout primitives + the existing
drag system — no new mechanics in the underlying layers, just a
composition pattern + a small gate added to `createLayoutController`.

The locked surface ships:

1. **`createReorder`** — primitive hook that owns the pointer +
   center-cross logic. Takes a controlled `Accessor<T[]>` + `Setter<T[]>`,
   returns `{ groupProps, itemProps }` that the user spreads on their
   own container and item elements.
2. **`<Reorder.Group>` + `<Reorder.Item>`** — JSX-level wrappers
   around `createReorder`. Group defaults to `<ul>`, Item defaults to
   `<li>`, both `as`-overridable. Item extends `MotionOptions` so
   per-item `animate` / `exit` / `transition` / lifecycle hooks all
   work the same way they do on a `<motion.li>`.
3. **Drag-suppressed layout** — a single check in
   `createLayoutController.runMeasurement` that gates off the FLIP
   for elements whose `whileDrag` flag is true. The dragged item's
   pointer-driven `drag` transform owns its visual position; siblings
   FLIP normally.

Design rationale and trade-offs are in
[ADR 0008](../adr/0008-reorder-primitive-and-components.md). Glossary
entries are in [CONTEXT.md](../../CONTEXT.md#reorder-020-work-in-progress).

## 2. Locked design decisions

All choices were grilled in a design session and recorded in
[CONTEXT.md](../../CONTEXT.md) and ADR 0008. Summary:

| # | Decision | Locked answer | Reference |
|---|---|---|---|
| 1 | **Surface shape** | Primitive `createReorder` + thin `<Reorder.Group>` / `<Reorder.Item>` wrappers. Primitive is the foundation; components are a ~30-line shim per file. | ADR 0008 |
| 2 | **Identity model** | Implicit reference identity in primitive (the item IS the key, same as `<For>`). Explicit `value` prop on the component wrapper so JSX nodes can be bound to array slots. Duplicate values: undefined behavior, documented. | ADR 0008 |
| 3 | **Axis support** | `"x"` and `"y"` from launch, default `"y"`. Mirrored math; same code path. No auto-detection. 2D / grid-style reorder out of scope (additive later if needed). | This plan §3 |
| 4 | **`values` / `onReorder` shape** | Explicit `Accessor<T[]>` + `Setter<T[]>`. Options object also accepts `ReorderOptions \| Accessor<ReorderOptions>` for reactive axis-switching. | This plan §3 |
| 5 | **When `onReorder` fires** | Live during drag, per center-crossing. Single source of truth (`values` IS what's rendered). No preview state. | ADR 0008 |
| 6 | **Sibling overlap detection** | Center-cross — dragged item's center along the axis passes a sibling's center → swap. Multi-crossing-per-frame supported. No debounce. | ADR 0008 |
| 7 | **Drag initiation** | Whole item draggable by default. Optional handle via the existing `createDragControls` primitive: pass `dragControls` + `dragListener: false` on the item. | This plan §4 |
| 8 | **Keyboard a11y** | Drag-only in v1. `createReorderKeyboard` deferred to a follow-up primitive. Documented gap; will be purely additive. | ADR 0008 |
| 9 | **Children pattern** | User-provided `<For>` as children of `<Reorder.Group>`. Composes with `<Presence>` for exit animations. | ADR 0008 |
| 10 | **Container tags** | `<Reorder.Group>` defaults to `<ul>`, `<Reorder.Item>` defaults to `<li>`. Both `as`-overridable. Item defaults don't auto-adjust when Group's `as` changes — user keeps tags coherent. | This plan §3 |
| 11 | **Drag-suppressed layout mechanism** | Existing `whileDrag` gesture-state-machine flag is the gate. Single check at the top of `createLayoutController.runMeasurement`. No new flag. | ADR 0008 |

## 3. Public API surface

### 3.1 `createReorder` primitive

Lives in `packages/motion/src/primitives/createReorder.ts`.

```ts
import type { Accessor, Setter } from "solid-js"
import type { DragControls } from "../types"

export type ReorderOptions = {
  /** Drag + center-cross axis. Default: "y". */
  axis?: "x" | "y"
}

export type ReorderItemOptions = {
  /**
   * When false, the item does NOT install a whole-item pointer
   * listener. Pair with `dragControls` to wire drag initiation to a
   * custom handle. Default: true.
   */
  dragListener?: boolean
  /**
   * Handle for explicit drag initiation. Composes with
   * `createDragControls()`. The handle's `onPointerDown` calls
   * `controls.start(event)` to start the drag.
   */
  dragControls?: DragControls
}

export type ReorderItemProps = {
  // The exact shape of the props returned by `itemProps(value)` —
  // these get spread onto the user's per-item element. Internally it's
  // a `MotionOptions` payload with `layout: true` + `drag: <axis>`
  // pre-set, plus a ref callback so the primitive can read the item's
  // bcr during pointermoves.
  ref: (el: HTMLElement) => void
  layout: boolean
  drag: "x" | "y"
  // ...plus any MotionOptions a downstream caller wires through
  // (e.g., the component wrapper's per-item motion props).
}

export type ReorderGroupProps = {
  ref: (el: HTMLElement) => void
  // ...any element-level wiring needed (no event handlers in v1; the
  // pointer listeners attach per-item).
}

export function createReorder<T>(
  values: Accessor<T[]>,
  setValues: Setter<T[]>,
  options?: ReorderOptions | Accessor<ReorderOptions>,
): {
  groupProps: ReorderGroupProps
  itemProps: (value: T, options?: ReorderItemOptions) => ReorderItemProps
}
```

The primitive returns props CALLABLES rather than reactive objects so
that each invocation can capture per-call options without re-instantiating
the entire reorder context.

### 3.2 `<Reorder.Group>` / `<Reorder.Item>` components

Lives in `packages/motion/src/reorder.tsx`.

```ts
import type { JSX, Setter, Accessor } from "solid-js"
import type { MotionOptions, DragControls } from "./types"

export type ReorderGroupComponentProps<T> = {
  values: Accessor<T[]>
  onReorder: Setter<T[]>
  /** Drag + center-cross axis. Default: "y". */
  axis?: "x" | "y"
  /** Container tag. Default: "ul". */
  as?: keyof JSX.IntrinsicElements
  children: JSX.Element
}

export type ReorderItemComponentProps<T> = MotionOptions & {
  value: T
  /** Item tag. Default: "li". */
  as?: keyof JSX.IntrinsicElements
  dragListener?: boolean
  dragControls?: DragControls
  children: JSX.Element
}

export const Reorder: {
  Group: <T>(props: ReorderGroupComponentProps<T>) => JSX.Element
  Item: <T>(props: ReorderItemComponentProps<T>) => JSX.Element
}
```

`<Reorder.Group>`:
- Calls `createReorder(() => props.values(), props.onReorder, () => ({ axis: props.axis ?? "y" }))` once at setup.
- Internally wraps children in `<LayoutGroup>` (no `dependency` prop —
  the parent-MO catches `<For>` reorders naturally).
- Renders `<Dynamic component={props.as ?? "ul"} {...groupProps}>{props.children}</Dynamic>`.

`<Reorder.Item>`:
- Reads the group's `itemProps` via a Reorder-internal context (provided by `Reorder.Group`).
- Splits its props into `{ value, as, dragListener, dragControls }` vs the rest (which is a `MotionOptions` payload).
- Calls `groupCtx.itemProps(props.value, { dragListener, dragControls })`.
- Merges the result with the user's `MotionOptions` (the user can NOT override `layout` or `drag` — those are wrapper-managed).
- Renders `<Dynamic component={props.as ?? "li"}>` via `useMotion()` so all `MotionOptions` features (animate, exit, transition, etc.) compose normally.

## 4. Implementation

### 4.1 `createReorder` primitive

The primitive owns four pieces of state:

1. **Group element ref** — captured by `groupProps.ref`. Used for the
   primitive's pointermove math (and for future drag-bounds work).
2. **Item element refs** — captured by each item's `itemProps(value).ref`.
   Stored in a `Map<T, HTMLElement>` keyed by item value.
3. **Active drag context** — `{ itemValue, pointerStart, axis }` set on
   pointerdown of any item, cleared on pointerup.
4. **Per-item bcrs at drag start** — snapshot of every item's
   `getBoundingClientRect()` taken once at pointerdown. Used as the
   "starting position grid" for center-cross detection. Re-measured
   when `values` updates during the drag (because Solid's `<For>` has
   reordered DOM nodes).

The pointer flow:

1. **`onPointerDown` on an item (whole-item drag):**
   - Capture pointer to the item element.
   - Resolve `axis` from current options.
   - Set `whileDrag = true` on the item's gesture state machine (this
     is what gates the layout FLIP — §4.3).
   - Snapshot every item's bcr into the per-item-bcr map.
   - Start the existing drag's pan-state tracking (writes to the
     item's `x` / `y` MotionValues as the user drags).

2. **On each `onPointerMove`** (handled by motion-dom's drag pipeline,
   we hook into the move via the drag's per-frame callback):
   - Read the dragged item's projected center along the axis:
     `dragStartCenter + currentDragOffset`.
   - Walk the siblings (from the value-to-element Map, in `values()`
     array order) starting from the dragged item's current array
     index. For each sibling:
     - If dragged moved in the `+axis` direction: check siblings
       AFTER the dragged item. A sibling B is "crossed" when
       `draggedCenter > siblingCenter`.
     - If dragged moved in the `-axis` direction: check siblings
       BEFORE the dragged item. A sibling B is "crossed" when
       `draggedCenter < siblingCenter`.
   - For each crossed sibling, swap dragged + sibling in `values()`
     via `setValues`. Recompute the dragged item's new array index.
     Continue checking for more crossings against the now-updated
     order.
   - After the walk, re-snapshot per-item bcrs (Solid's `<For>` has
     reordered the DOM nodes; their bcrs have shifted).

3. **`onPointerUp` / `pointercancel`:**
   - Set `whileDrag = false`. The dragged item's drag transform now
     animates to zero against its current slot via the existing drag
     pipeline. The item visually settles into wherever the user
     dropped it.

### 4.2 Center-cross detection algorithm

Pseudocode for the per-pointermove walk:

```ts
function detectAndSwapCrossings(
  draggedValue: T,
  draggedCenterAlongAxis: number,
  axis: "x" | "y",
): void {
  let currentArray = values()
  let draggedIndex = currentArray.indexOf(draggedValue)
  if (draggedIndex < 0) return  // item removed from array externally — abort

  // Walk both directions; usually only one direction will have
  // crossings since the drag is moving along one direction.
  let didSwap = true
  while (didSwap) {
    didSwap = false
    const direction =
      draggedCenterAlongAxis > centerOfItemAt(currentArray, draggedIndex, axis)
        ? "+1"
        : "-1"

    const neighborIndex = draggedIndex + (direction === "+1" ? 1 : -1)
    if (neighborIndex < 0 || neighborIndex >= currentArray.length) break

    const neighborCenter = centerOfItemAt(currentArray, neighborIndex, axis)
    const crossed =
      (direction === "+1" && draggedCenterAlongAxis > neighborCenter) ||
      (direction === "-1" && draggedCenterAlongAxis < neighborCenter)

    if (crossed) {
      const next = swap(currentArray, draggedIndex, neighborIndex)
      setValues(next)
      currentArray = next
      draggedIndex = neighborIndex
      didSwap = true
    }
  }
}
```

The `while (didSwap)` loop handles fast drags that cross multiple siblings
in one frame. After each swap, the dragged item's index updates and the
loop re-checks against the new neighbor.

**Edge cases handled:**
- **Variable-height items.** Center-cross is per-axis-center regardless
  of size; no special-case needed.
- **Dragged item removed from `values` externally.** `indexOf` returns
  -1; we early-return and let the drag complete visually (the dragged
  item's drag transform still settles, but no further reorders fire).
- **New items added during drag.** They appear in `values`; their bcrs
  get snapshotted on the next pointermove (re-snapshot happens after
  each swap). The dragged item's center-cross logic naturally
  integrates them as it walks the array.

### 4.3 Drag-suppressed layout via `whileDrag`

A single check added at the top of `createLayoutController.runMeasurement`:

```ts
function runMeasurement(): void {
  // ... existing degenerate-rect skip and baseline path ...

  // Reorder drag-suppression: when this element is actively being
  // dragged (whileDrag === true in its gesture state machine),
  // skip the FLIP. The pointer-driven drag transform owns visual
  // position; firing layout would compete with it.
  //
  // Silently update `first` to the new measurement so when the drag
  // ends and the next trigger fires, the baseline reflects the
  // current slot (no stale rect carried across the drag lifetime).
  if (activeStore.whileDrag) {
    first = last
    return
  }

  // ... existing delta computation + applyFlip ...
}
```

The `activeStore` is the gesture state machine's reactive store, which
the controller already has access to via the createMotion → createLayoutController
config. No new wiring needed beyond reading `activeStore.whileDrag`.

**Note on the silent-baseline-update.** Without it, the dragged item's
`first` rect stays at its pre-drag position. When the drag ends and the
next trigger fires (RO / parent-MO), the controller computes a delta
between pre-drag-position and post-drop-position — which is non-zero
if reorder swapped the dragged item to a different slot — and would fire
a FLIP. We don't want that FLIP because the drag transform's own
release-animation handles the settle. Silently updating `first` to the
post-reorder position keeps the controller in sync without firing
unintended animations.

### 4.4 Component wrappers

`<Reorder.Group>`:

```tsx
import { Dynamic } from "solid-js/web"
import { createContext, useContext, splitProps } from "solid-js"
import { LayoutGroup } from "./layout-group"
import { createReorder } from "./primitives/createReorder"

type GroupContext = ReturnType<typeof createReorder>

const ReorderGroupContext = createContext<GroupContext | undefined>(undefined)

function Group<T>(props: ReorderGroupComponentProps<T>): JSX.Element {
  const [own, rest] = splitProps(props, ["values", "onReorder", "axis", "as", "children"])
  const reorder = createReorder(own.values, own.onReorder, () => ({
    axis: own.axis ?? "y",
  }))
  return (
    <ReorderGroupContext.Provider value={reorder}>
      <LayoutGroup>
        <Dynamic component={own.as ?? "ul"} {...reorder.groupProps} {...rest}>
          {own.children}
        </Dynamic>
      </LayoutGroup>
    </ReorderGroupContext.Provider>
  )
}
```

`<Reorder.Item>`:

```tsx
function Item<T>(props: ReorderItemComponentProps<T>): JSX.Element {
  const reorder = useContext(ReorderGroupContext)
  if (!reorder) {
    throw new Error("<Reorder.Item> must be a descendant of <Reorder.Group>")
  }
  const [own, motionProps] = splitProps(props, [
    "value",
    "as",
    "dragListener",
    "dragControls",
    "children",
  ])
  const itemProps = () =>
    reorder.itemProps(own.value, {
      dragListener: own.dragListener,
      dragControls: own.dragControls,
    })
  // Compose itemProps (layout: true, drag: axis, ref) with user's MotionOptions.
  // The user CANNOT override `layout` or `drag` — wrapper-managed.
  return (
    <motion[own.as ?? "li"]
      {...motionProps}
      {...itemProps()}
    >
      {own.children}
    </motion[own.as ?? "li"]>
  )
}

export const Reorder = { Group, Item }
```

(The actual `motion[tag]` access uses the motion proxy; `Dynamic` shape
above is illustrative.)

### Test infrastructure

- **`getBoundingClientRect` mocking.** Same approach as the layout
  suite: stub `el.getBoundingClientRect` per test to seed measured
  positions.
- **Pointer event simulation.** Use `@solid-primitives/event-listener`-style
  helpers or raw `el.dispatchEvent(new PointerEvent(...))` to simulate
  the drag lifecycle.
- **Motion mock.** Continue mocking `motion`'s `animate` per existing
  pattern (see `tests/primitives/gesture-state.test.tsx`).

### TDD discipline

Write the test, watch it fail, implement, watch it pass. Mirror the
pattern from the layout suite. Center-cross detection in particular
benefits from TDD — the multi-crossing-per-frame and direction-flip
edge cases are easy to miss without a test driving each.

3. **`ReorderWithExit.tsx`** — vertical list inside `<Presence>` with

   button plays its exit; siblings FLIP into the new positions.

import { Reorder } from "solidjs-motion"

const ITEMS = [
  { id: 1, label: "First" },
  { id: 2, label: "Second" },
  { id: 3, label: "Third" },

export function App() {
  const [items, setItems] = createSignal(ITEMS)

      </For>

  )
}

### Recipe 17 — Reorder with a drag handle

```tsx
import { createSignal } from "solid-js"
import { Reorder, createDragControls } from "solidjs-motion"

export function App() {
  const [items, setItems] = createSignal(ITEMS)
  return (
    <Reorder.Group values={items} onReorder={setItems}>
      <For each={items()}>
        {(item) => {
          const controls = createDragControls()
          return (
            <Reorder.Item
              value={item}
              dragControls={controls}
              dragListener={false}
              class="list-item"
            >
              <span class="content">{item.label}</span>
              <button
                class="handle"
                aria-label="Drag to reorder"
                onPointerDown={(e) => controls.start(e)}
              >
                ::
              </button>
            </Reorder.Item>
          )
        }}
      </For>
    </Reorder.Group>
  )
}
```

## 9. Step-by-step execution order

Each step is one self-contained commit (mirroring the layout plan's
discipline). Steps 1–4 are the primitive + plumbing; 5 is the
component pair; 6–8 are demos + docs.

1. **Add types.** Modify `packages/motion/src/types.ts`: add
   `ReorderOptions`, `ReorderItemOptions`. Compile-check.
2. **Add the drag-suppression gate.** Modify
   `packages/motion/src/primitives/createLayoutController.ts`: add the
   `if (activeStore.whileDrag) { first = last; return }` check at the
   top of `runMeasurement`. Add a test
   (`tests/reorder/drag-suppression.test.tsx`) that exercises it —
   a `<motion.div layout drag>` element being dragged should NOT fire
   FLIPs even as its bcr changes due to drag transform.
3. **Implement `createReorder` (primitive).** Create
   `packages/motion/src/primitives/createReorder.ts`. Tests:
   `tests/reorder/primitive.test.tsx` (basic shape),
   `tests/reorder/center-cross.test.tsx` (detection math),
   `tests/reorder/edge-cases.test.tsx` (mid-drag mutations),
   `tests/reorder/axis.test.tsx` (both axes).
4. **Export from index.** `packages/motion/src/index.ts`: export
   `createReorder`, `ReorderOptions`, `ReorderItemOptions`. Update
   `tests/types.test-d.ts` for the public shape.

   `packages/motion/src/reorder.tsx` with `Reorder.Group` /
   `Reorder.Item` and the internal `ReorderGroupContext`. Export `Reorder`
